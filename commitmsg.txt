fix(regions): a repeat must match by NAME at the same phase; class is a per-page call

Follow-up to 67ef928, after testing both settings as Ali asked rather than guessing.

THE BUG THE THRESHOLD WAS HIDING
Removing the `>= 3` threshold in 67ef928 let a run of TWO collapse, and that silently
deleted x.com's rail: primaryColumn and sidebarColumn are different places that happen
to have one region child each, so they matched on shape, and the outline printed the
feed with a count and never showed the rail at all. The number was load-bearing for the
wrong reason.

PROPER FIX — no number involved: the repetition key is shape + the element's own NAME
compared at the same phase of the period. The shape says the subtree looks the same; the
name says it IS the same thing.
  - identical names still collapse at any length (cellInnerDiv x9, content-section x4);
  - an alternating run still collapses, each phase keeping its own name;
  - two differently-named places never merge, so nothing is hidden.
A collapsed run now also carries every DISTINCT name it holds, so a group can never
imply that its members are identical when they are not.

CLASS: DECIDED FROM THE PAGE, NOT BY PREFERENCE
Measured both ways. With classes always on, x.com's outline was 242 lines of which 187
were CSS-in-JS hashes (.css-g5y9jx, .css-146c3p1) and MDN's went from 7 useful lines to
~50. With classes always off, books.toscrape — which names its whole layout with class
only (div.page > article.product_pod) — produced ONE line and no map at all.
So: run with the page's structural words first, and consult classes only when that
produced no structure whatsoever. Per-page and derived from the page. This is not a
filter — the classes are in the inventory and in page_slice either way.
